# 01 环境准备

## 盒子上要做的（一次性）

1. 盒子联网，记下 IP（本例 `192.168.1.100`）
2. 设置 → 关于本机 → 连点「版本号」打开开发者选项
3. 开发者选项里打开 **ADB 调试 / 网络调试**
4. 建议把盒子的 IP 在路由器里设为静态，避免重启后变化

## 电脑上要装的

| 工具 | 用途 | 安装 |
|---|---|---|
| ADB (platform-tools) | 所有操作都靠它 | `winget install Google.PlatformTools` |
| JDK 17 | 编译用（不编译可不装） | `winget install EclipseAdoptium.Temurin.17.JDK` |
| Android SDK | 编译用（不编译可不装） | cmdline-tools + `sdkmanager "platforms;android-36" "build-tools;35.0.0"` |
| Python + Pillow + opencv | logo 脚本、天气二维码解码（可选） | `pip install pillow opencv-python` |

设置环境变量：

```bash
export ANDROID_HOME=/path/to/android-sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools
```

## 连通性验证

```bash
adb connect 192.168.1.100:5555
adb devices                  # 应看到 192.168.1.100:5555  device
adb shell getprop ro.product.model   # 应返回 Q5001
```

连不上先排查：

- 盒子是不是休眠了（休眠时 ADB 完全无响应，遥控器按一下唤醒）
- 地址和端口对不对（有些固件是 5555，有些是随机端口）
- `adb disconnect` 后重连，或 `adb kill-server`

## 本仓库脚本的环境坑（已内置处理）

- **Git Bash 下 adb daemon 会在每条命令结束后被清掉**，所以脚本里每条命令开头都重新 `connect`
- **`adb pull` 的远程路径会被 Git Bash 转成 Windows 路径**，所以统一走 `lib.sh` 里的 `adb_pull` / `adb_push`（带 `MSYS_NO_PATHCONV=1`）
- 脚本在 Windows 的 Git Bash 下验证过；Linux/macOS 只需确认 `adb` 在 PATH 里

跑 `./scripts/01-setup-env.sh` 可以一次性看到还缺什么。
