# 创维小湃 P3 盒子改造手册

> 适用机型：创维小湃盒子 P3（型号 **Q5001**，机型 `cupid_p2`，全志 H616）
> 目标：把原厂桌面换成 Aerial TV（航拍屏保桌面），系统瘦身，开机可控，全程免 root。
> 实测环境：Android 10（API 29），2 GB 内存 / 16 GB 存储，**32 位用户空间**。

---

## 一、为什么这盒子需要专门适配

四件事决定了整套方案，不知道这些会反复踩坑：

| 固件行为 | 后果 | 我们的做法 |
|---|---|---|
| **HOME 前缀白名单**：只认 `com.ktcp.launcher`、`com.skyworthdigital.sky2dlauncher` 等前缀 | 第三方桌面装上也当不了默认桌面 | Aerial 的 `applicationId` 改成 `com.ktcp.launcher.aerial`（Java 命名空间仍是 `app.orchard.tv`） |
| **拦截第三方开机广播** | 任何自启 App 都收不到 `BOOT_COMPLETED` | 由桌面自己拉起目标应用（Aerial 的「开机打开应用」） |
| **每次开机把 `screensaver_components` 写回广告组件** | 换好的屏保每次重启就没了 | 每次开机后跑一次 `deploy.sh --optimize`，或挂看门狗 |
| **云端「系统控制列表」周期性把停用的包恢复启用** | 语音助手、媒体中心反复复活 | 4 个最顽固的包直接 `pm uninstall -k --user 0`（见第五节） |

另一个硬约束：**用户空间是纯 32 位**（`ro.product.cpu.abi = armeabi-v7a`，`ro.zygote = zygote32`）。
只带 `arm64-v8a` 的 APK 会直接 `INSTALL_FAILED_NO_MATCHING_ABIS`，与 root、签名、安装方式都无关。

## 二、准备

1. 盒子开机，遥控器进入 **设置 → 关于 → 连续点按版本号** 打开开发者选项，开启 **USB/网络调试（ADB）**。
2. 盒子与电脑同一局域网，记下盒子 IP（路由器后台或 `设置 → 网络`）。
3. 电脑装 Android platform-tools（`adb`），并验证连通：

```bash
adb connect 192.168.1.x:5555
adb -s 192.168.1.x:5555 shell getprop ro.product.model    # 应输出 Q5001 之类
```

> 盒子休眠时 ADB 完全无响应（ping 通、5555 关闭）。先按遥控器唤醒，或拔电源重启。

## 三、三步部署

```bash
# 1. 设定盒子地址（写进 box.conf 可免去每次输入）
export BOX_TARGET=192.168.1.x:5555

# 2. 一条命令跑完全流程：装桌面 → 设 HOME → 补权限 → 卸载顽固包 → 系统优化
bash deploy.sh

# 3. 拔电源重启，起来后补回屏保
bash deploy.sh --optimize
```

`deploy.sh` 的四种模式：

| 命令 | 作用 | 耗时 |
|---|---|---|
| `bash deploy.sh` | 全流程部署（已装过的机器可重复跑，幂等） | 约 1 分钟 |
| `bash deploy.sh --check` | 只体检：HOME、屏保、停用包、常驻进程、内存，不改任何东西 | 约 10 秒 |
| `bash deploy.sh --optimize` | 只重跑优化，重启后补回屏保和停用包 | 约 10 秒 |
| `bash deploy.sh --watch` | 看门狗：被固件恢复的包和屏保自动补回，常驻 | — |

可选：`--build` 从源码编译 Aerial（需 JDK 17 + Android SDK，首次约 9 分钟），
`--dry-run` 只报告不动盒子，`--interval 60` 改看门狗轮询间隔。

**开机自动打开某个应用**：在 Aerial 里设置（设置 → 开机打开的应用）。
本仓库的补丁已把这段跳转延迟 5 秒——不加延迟的话桌面一冒头就跳走，看着像根本没进桌面。

## 四、原理

### 桌面接管

Aerial 是上游开源项目 `pengchujin/aerial-tv`，我们只改四处（`patches/aerial-tv-p3.patch`）：

1. `applicationId` → `com.ktcp.launcher.aerial`，绕过 HOME 前缀白名单
2. 新增 `AutostartBridge.kt`：开机首次进桌面时显式拉起定时启动服务（备用通道）
3. `openBootSource()` 内部延迟 5 秒再跳转（三条路径 boot / wake / screen-on 共用）
4. 常量与 import 跟随上游结构调整

装完必须 `cmd package set-home-activity`，并确认 `resolve-activity` 真的落到 Aerial，
才能停用官方桌面——顺序反了会卡开机动画。

### 权限

装完 Aerial 不会自动拿到关键权限，缺了它只是个空壳（屏保切不了、HOME 被抢回救不回来）。脚本分三类补齐：

- **运行时权限**：`pm grant`（`WRITE_SECURE_SETTINGS`、`PACKAGE_USAGE_STATS` 等）
- **appops**：`WRITE_SETTINGS`、`REQUEST_INSTALL_PACKAGES`、`SYSTEM_ALERT_WINDOW`（`pm grant` 会抛异常）
- **服务登记**：通知监听 + 无障碍守护服务。无障碍列表**必须保留厂商原有条目**，
  直接覆盖会关掉创维语音助手的无障碍。

### 系统瘦身

`config/disable-list.txt` 里 22 个包用 `pm disable-user --user 0` 停用（不需要 root）。
官方桌面不在默认停用范围里——脚本会显式跳过，因为它是开机最后一道保险。

### 屏保

出厂屏保是创维广告组件，固件每次开机写回。而且广告包 `ott.advert.app` 在我们的卸载清单里，
于是屏保指向一个不存在的服务 = 完全没有屏保。所以每次开机后要跑一次 `--optimize` 把它改回
`com.ktcp.launcher.aerial/app.orchard.tv.dream.AerialDream`。

## 五、为什么这 4 个包要「卸载」而不是「停用」

`config/uninstall-list.txt`：

```
com.skyworthdigital.ottstatsv2
com.skyworthdigital.ott.advert.app
com.skyworthdigital.skyappupdate
com.skyworthdigital.logcollector
```

固件里的 `com.skyworthdigital.skycommonpropertymanager`（system uid）开机约 60 秒后拉取一份
厂商「系统控制列表」，逐个 `setApplicationEnabledSetting(ENABLED)` 把我们停用的包恢复回来。
**包对 user 0 不存在时，这一步抛 `Unknown package`，恢复动作自然失效。**

所以：`pm uninstall -k --user 0 <包名>`。`-k` 保数据，APK 仍留在 `/system`，随时可还原：

```bash
adb shell pm install-existing <包名>     # 单个还原
bash restore.sh --apps                   # 批量还原
```

脚本卸载前会把 APK 复制到盒子 `/sdcard/p3-backup/` 作为额外保险。

剩下的语音助手、媒体中心只停用、不卸载（卸了会影响遥控器语音），因此每次开机仍可能被恢复，
靠 `--optimize` 或看门狗补回。

## 六、日常维护

```bash
bash deploy.sh --check       # 随时看状态
bash deploy.sh --optimize    # 每次重启后跑一次（10 秒）
bash deploy.sh --watch       # 或者挂个看门狗常驻，自动补
```

看门狗挂在 Windows 计划任务（登录时触发），或每 5 分钟跑一次单次模式：

```
schtasks /create /tn "SkyworthBoxWatch" /sc minute /mo 5 /f ^
  /tr "bash -lc 'cd /path/to/repo && BOX_TARGET=192.168.1.x:5555 bash deploy.sh --watch --once'"
```

日志在 `backup/watch.log`。

## 七、故障排查

| 现象 | 原因与处理 |
|---|---|
| 装完桌面开不了机 / 卡开机动画 | 官方桌面停了但第三方没接管 HOME。`adb shell pm enable com.skyworthdigital.sky2dlauncherv4` 后重启 |
| `install` 成功但版本没变 | 包名错或路径被 Git Bash 转换。Windows 下必须用 `C:/...` 形式，脚本已用 `win_path()` 处理 |
| `INSTALL_FAILED_NO_MATCHING_ABIS` | APK 只有 `arm64-v8a`，盒子是纯 32 位。换 `armeabi-v7a` 或通用包，无其它解 |
| 屏保又变回创维广告 | 固件开机写回，属预期。跑 `--optimize` |
| 语音助手/媒体中心又活了 | 云端列表恢复，属预期。跑 `--optimize` 或看门狗 |
| 重启后 Aerial 没跳转 | 网络未就绪（Aerial 最多等 20 秒），或目标应用冷启动慢。看 `adb logcat \| grep AerialDiag` |
| 盒子突然连不上 | 多半休眠了，遥控器唤醒。不是脚本问题 |
| `settings get global <key>` 返回 null | adb 重定向下常见，改用 `settings list global \| grep <key>` |
| 天气城市不对 | Aerial 按 IP 猜，在 Aerial 设置里手动指定 |
| 桌面图标换了不生效 | Aerial 读 `android:banner`（320×180），不是 `ic_launcher` |

日志关键字：`adb logcat | grep -E "allow home apk|block home apk"` 看白名单是否放行，
`adb logcat | grep AerialDiag` 看桌面的开机决策。

## 八、完全还原

```bash
bash restore.sh              # 参数 + 应用 + 官方桌面
bash restore.sh --params     # 只还原参数与屏保
bash restore.sh --apps       # 只恢复被停用/卸载的应用
bash restore.sh --home       # 只把桌面还给官方
bash restore.sh --uninstall  # 卸掉 Aerial
```

## 九、已知限制

- **装不了 32 位以外的应用**：硬件层面的 32 位用户空间，软件绕不过去。
- **每次开机都要补一次**：屏保与两个常驻包会被固件改回，这是固件行为不是配置问题。
- **停用官方桌面有风险**：Aerial 崩溃时没有回退桌面，需要 ADB 救。
- **不要用 Aerial 控制中心的「检查更新」**：它会下载官方 `app.orchard.tv` 装成第二个应用，
  和我们改过包名的版本并存，HOME 归属会乱。
