# 00 改造全过程：从原厂盒子到"开机就能看"

这篇是完整历程，不是教程目录。目的有两个：想动手的人能照着走一遍；不想动手的人能看到
**哪些路是死的**，省下试错时间。分步命令在 [01](01-环境准备.md) ~ [04](04-定时启动部署.md)，
这里讲取舍。

---

## 一、先把目标说清楚

"优化系统"是个很虚的说法。真正可验收的目标只有一条：

> **老人按下电源键，几秒后直播画面自己出来，中间不需要做任何选择。**

反推出来要满足三件事：

1. 开机不能停在官方桌面（那是广告 + 付费点播入口，老人会迷路）
2. 桌面要能看（字大、图块少、遥控器焦点明确）
3. 从桌面到直播要自动，但**不能锁死**——自己想看点别的时要能拦住

第 3 条最容易被忽略。纯自动跳转的盒子，一旦老人想换个台或看个本地视频，就得跟它抢时间。
所以最终做成了"**倒计时浮层 + 按任意键取消**"，而不是静默跳转。

---

## 二、摸底：先确认这台机器有没有改造空间

三个命令就能判断（`00-doctor.sh` 会一次性跑完）：

```bash
adb shell getprop ro.product.cpu.abi        # armeabi-v7a → 32 位用户空间
adb shell getprop ro.build.version.release  # 10
adb shell getprop ro.serialno               # 序列号（别外传）
```

实测结论：全志 H616、2 GB 内存、Android 10、32 位用户空间、**无 root**。
`adb root` 直接报 `adbd can't run as root`，`/system` 只读。

这一步最重要的收获不是参数，而是确认了**不需要 root 也能做**：
这代固件把 `pm disable-user`、`cmd package set-home-activity`、`settings put` 都对 shell 用户放开了。
整套方案就架在这三个命令上。

> 32 位用户空间是个隐藏坑：后面所有自编译 APK 都不能只打 `arm64-v8a`，否则装上就崩。

---

## 三、第一道墙：官方桌面换不掉

装上第三方桌面后，按 HOME 键还是回官方桌面，`cmd package set-home-activity` 也不生效。

翻 logcat 才看清：

```
PackageManager: block home apk: com.example.launcher
PackageManager: allow home apk: com.ktcp.launcher.xxx
```

系统在 framework 层按**包名前缀**过滤 HOME 候选。白名单里有个 `com.ktcp.launcher`，
而系统里根本没有这个包——它只是个前缀占位。

**于是换了个思路：不改系统，改自己的包名。**

- CleanYourTV 的 `applicationId` 改成 `com.ktcp.launcher`
- 后来换 Aerial，改成 `com.ktcp.launcher.aerial`

代码一行不用动（Java 命名空间还是原来的），只是安装后的组件全名变成
`com.ktcp.launcher.aerial/app.orchard.tv.MainActivity` 这种"混血"形式。

试过但**完全无效**的方案，不要重复：

| 方案 | 结果 |
|---|---|
| `settings put global enable_launcher_components <pkg>` | 开机被系统服务重置 |
| `setprop sys.launcherlist.enable 0` | 同上，且属性是只读的 |
| 停用官方桌面包 | 系统直接回落到 `com.android.provision`，更糟 |
| 改 `/system` 里的配置 | 分区只读，除非刷机 |

## 四、第二道墙：开机自启被全链路封死

桌面解决了，接着要"开机后自动拉起定时启动"。常规做法是 `BOOT_COMPLETED` 广播，结果：

```
E BroadcastQueue: Block auto start app from broadcast: com.ktcp.launcher.autostart
```

一圈试下来，全部失败：

- `BOOT_COMPLETED` receiver ❌
- 申请 `RECEIVE_BOOT_COMPLETED` + 开机白名单 ❌
- 借白名单里的空包名（`com.android.provision`）❌
- `monkey -c LAUNCHER` 清 stopped 态 ❌
- 前台服务自己在 `onCreate` 里 `startForeground` 救 ❌
- 连预装的搜狗输入法都被同一条规则拦 ❌

**最后绕开的办法：不申请自启，让桌面代劳。**

桌面是系统唯一保证会启动的应用。只要在桌面**开机首次启动**的那一刻，由它显式
`startForegroundService()` 拉起我们的服务，就等于完成了自启——"前台应用显式启动服务"
是这套固件没有封的口子。

Aerial 本身就有 `firstStartSinceBoot()`（拿 `Settings.Global.BOOT_COUNT` 做去重），
在它后面挂一个 30 行的 `AutostartBridge` 就够了。补丁见 `patches/aerial-tv-p3.patch`。

> **一个反直觉的发现**：`BOOT_COMPLETED` 不是永远收不到。包处于非 stopped 态时，
> 系统确实会派发——我们后来在 logcat 里两次抓到 `BootReceiver` 真的跑起来了。
> 但它的 `Intent` 没带 action，被服务当成"未知来源"，用了更长的缓冲，
> 反而把桌面发来的计时覆盖掉，导致开机要等 20 多秒。这就是 v4.2 修复的那个 bug：
> **服务对 arm 做幂等，一次开机只认第一次**。

## 五、系统瘦身：只动系统应用，第三方一律不碰

原则：**别人的软件不擅自删，系统自带的能停就停。**

用 `pm disable-user` 停了 18 个常驻（语音助手、SkyMediaCenter、自检工具、广告服务等），
调了 6 项参数（动画缩放 0、关闭 heads-up 通知等），清了缓存。

几个要注意的点：

- `pm disable-user` 之后进程不一定马上退，要 `am force-stop` 补一刀，否则内存没释放
- **官方桌面先别停**，等第三方桌面确认接管、重启验证过一次之后再处理
- 屏保默认是广告组件 `com.skyworthdigital.ott.advert.app`，可以换成 Aerial 自带的航拍屏保
- 但**固件每次开机都会把它写回广告组件**，重装 Aerial 也会重置——不是设置一次就完事，
  所以脚本每次跑完都会顺手补一次（`lib.sh` 的 `restore_dream()`）

清理完的实际收益：内存可用量上升、开机到桌面的时间缩短，动画卡顿明显减少。
机顶盒这种 2 GB 内存的设备，"少一个常驻"比"优化一个常驻"划算得多。

## 六、体感优化：真正花时间的是这些

功能跑通只用了两天，剩下的时间都在磨这些：

### 1. 从桌面到浮层的 9 秒

第一版要等 **26 秒**才弹窗。拆开看是三个问题叠在一起：

```
13:35:30.2  桌面显示完成
13:35:32.4  服务被 arm
13:35:56.2  浮层才出来     ← 23.8 秒
```

- 服务被 arm 了两次，第二次（来自 BootReceiver）覆盖了第一次，从更晚的时间点重新计时
- "未知来源"分支的兜底缓冲是 15 秒
- 单发 `postDelayed` 在刚开机繁忙的主线程上又迟到了约 3 秒

改法：幂等（只认第一次 arm）+ 绝对死线 + 250 ms 轮询自校正（用 `elapsedRealtime`，
休眠也不漂）。改完是 **9 秒**，其中 5 秒是用户自己设的延迟。

### 2. 界面

从"能用"到"敢给老人用"，改了四轮：

- 第一版是 Material 风格的卡片，字小、焦点不明显
- 换成仿 Apple TV 的极简风：近黑画布、纯白单强调色、胶囊控件、聚焦放大 1.06 倍
- 提醒浮层原来占屏幕 68%，缩小到 34%（336 dp），不遮住底下的东西
- "取消"按钮改成"还原"，点了就清空配置回到未设置——原来说明不直观

### 3. 图标

闹钟 logo 做了 5 个方案（浅玻璃盘 / 深色刻度 / 琥珀三档 / 分针穿出成箭头…），
最后选的是"白色圆环 + 内嵌箭头"，因为 48 px 下只有这个还认得出来。

两个技术细节：

- **矢量图不能用退化弧**。`a... 0 1,0 0.001,0` 这种写法 Android 会直接丢弃，
  圆环只画出一小截。必须用两段显式的半圆弧。
- **桌面图块读的是 `android:banner`（320×180 横图），不是方形 `ic_launcher`**。
  一开始换了方形图标没反应，查了很久。

### 4. 天气城市

Aerial 存的是经纬度不是地名，而且写在私有目录里（没 root 写不进）。
官方给了条路：控制中心里有个二维码，手机扫码打开一个带 token 的本地 HTTP 页面，
通过它 POST 城市名。脚本 `31-set-weather.sh` 干的就这事：
截图 → OpenCV 解二维码 → 拿到 token → 提交城市。

> 扫码前要先按一下方向上键把焦点移到状态栏，否则 MENU 会弹出图块菜单而不是控制中心。

## 八、如果重来一次

按重要性排序，这几件事应该先做：

1. **先跑体检再动手**。哪些应用在跑、能不能停，写清楚再改，比改完出问题再翻 logcat 快十倍。
2. **先确认"能不能换桌面"再投入做别的**。桌面换不掉的话，后面所有工作都白做。
3. **所有原值先落盘**。参数、停用清单、屏保组件，一个 `config/` 目录就够，回滚时救命。
4. **每改一处就重启验证一次**。这机器的行为在"冷启动"和"热切换"之间差别很大——
   很多问题只有重启才暴露（屏保被重置、自启被覆盖都是这么发现的）。
5. **别相信"应该可以"**。这台固件对每一条常规做法都有对应的一刀切。

## 九、成本

- 时间：功能跑通约两天，剩下的一周都在磨时序和视觉
- 风险：全程不刷机、不改系统分区，最坏情况是卸掉两个 APK 重启回原样
- 代价：`pm disable-user` 的 18 个系统应用会一直停着；想恢复跑 `40-restore.sh`

对一台本来要吃灰的老盒子来说，这个投入是值的——它现在每天都在用。
